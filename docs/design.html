提醒落在哪里 · 可选

菜单栏，还是刘海

 Claude 在等你  · 32s

菜单栏模式——图标进入事件态， 翼变琥珀，旁边一个圆点。安静，但要你正好瞥到那一片。

刘海模式——提示贴着摄像头两侧展开，正在屏幕正上方， 视线抬起来就撞上。更难忽略，也更打扰。

这台机器没有刘海。MacBookPro17,1（M1 13" 2020）是最后一代带 Touch Bar、 也是没有刘海的那一批。所以刘海模式对它无效—— 程序用 NSScreen.safeAreaInsets.top 自动探测，没有就把这个选项灰掉， 不给你一个点了没反应的开关。你另一台机器如果是 14/16 寸，那边就能用。

核心机制

翼即仪表

标识本身就是仪表。五根羽毛就是五条通道，颜色沿羽毛走了多远， 就是这条通道离出事还有多远。

不需要新开先例——房屋标准第 §7.1 衍生仪表例外 已经写过， 边界是一句话：标识可以作为仪表运动，不可作为识别运动。 PWE MAC MONITOR 用同一条例外，同一套渲染器。

阈值不用我们定

接口自己给 severity：normal / warning。 服务端比我们更清楚什么时候该慌。我们只负责把它画出来， 本地阈值仅作为离线降级时的兜底。

五条通道归一成 strain：静止 0，正好到 warm 是 0.72，正好到 hot 是 1.0。 刻度共享，所以「走到四分之三」在每根羽毛上意思一样—— 不管它数的是百分比、剩余分钟，还是一个「耗尽」的布尔值。

三态 · 面板尺寸 · 五色

Calm

全部实心。正常读数不该花掉你任何注意力。

Warm

越界的那根退出实心，尾段变暗轨。

Hot

只有越线的那根发光。都发光，发光就不是信号了。

菜单栏一色，面板五色。MAC MONITOR 做过实尺寸原型：22 点高的栏里每根羽毛约 1 点粗， 五种色调糊成一条斑驳的痕——认得出「出事了」，认不出「出什么事」。结论直接继承。

让密度成立的四条排列规则

三条列基线。 标签、数字、时间各自成列，跨分区也对齐—— 眼睛沿一条直线往下扫，不必每行重新找位置。

同类归组。 通道图例贴着仪表，窗口条彼此相邻，战绩独立成栏。 分隔线只画在组与组之间。

数字一律 tabular。 84% 跳到 85% 时，右边不许跟着抖。

颜色只标状态。 琥珀和红是警示，不是装饰。

主角会换人

大的那个数字不是固定的「五小时窗口」， 而是当前最紧的那一条。此刻是周窗口 84%，等它重置了， 主角自动让给别人。

两种外观不是反色，是换 token——琥珀金只在深蓝底出现， 浅底一律换深琥珀，由 Brand.accent 承担。

接口给的比想象中多

除了 five_hour / seven_day，响应里还有一个 limits[] 数组，每条带 kind、group、 percent、severity、resets_at、 is_active。

就照着 limits[] 写，别照着具名字段写。 响应里已经躺着一批当前为 null 的桶——按模型分的周额度、附加用量、 几个还没启用的名目。哪天它们有值了，按数组写的界面自己就多出一行， 按具名字段写的得改代码。

severity 直接告诉我们该不该报警，is_active 告诉我们此刻是哪条在卡人——面板里那个大数字选谁当主角，就看它。

一个仍然存在的坑

你的 Codex 是 plan_type: team， primary / secondary 都是 null， 实际状态是 workspace_member_credits_depleted。 它跟 Claude 的口径对不齐，界面上不能硬凑成两条一样的进度条—— CDX 那根羽毛显示的是状态，不是百分比。
