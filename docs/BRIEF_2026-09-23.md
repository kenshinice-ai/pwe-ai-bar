## 改了什么

### A. 会让数字出错的（最重要）

| # | 问题 | 修法 | 位置 |
|---|---|---|---|
| 1 | Claude 日志**按行计数**。一条回复按内容块写成多行，每行都重复同一个 `usage`，于是回合数、token 和等效成本被放大 | 按 `message.id + requestId` 去重：同一遍解析里的多行，各字段取最大值；跨文件、跨增量解析时由 `claims` 表挡住重复。缓存升到 **v5** | `Providers/Transcript.swift` 的 `digest` 与 `messageKey` |
| 2 | 价格表只认**完全相同**的模型名，带日期的 id（如 `claude-haiku-4-5-20251001`）一律按 $0 计 | `Pricing.canonical` 去掉日期、`@日期`、`[1m]` 后缀，并把 3.x 的写法换成表里的名字。**故意不做前缀匹配**：`claude-opus-5` 是 `claude-opus-5-5` 的前缀，但两者价格不同。表里新增 **`claude-opus-5-5`：$4 / $20，缓存读 0.05×** | `Core/Pricing.swift`、`Resources/pricing.json` |
| 3 | cask 的注释说设置里可以「移除钩子」，但代码里没有这个功能 | 新增 `HookProvider.uninstall`，护栏与安装相同：拒绝软链接、先备份、写入前文件已变就放弃。只删我们加的三条，设置页新增「移除」按钮 | `Providers/HookProvider.swift`、`App/SettingsView.swift` |

### B. 性能

| # | 问题 | 修法 |
|---|---|---|
| 4 | 每 20 秒把两棵日志树整个列一遍、逐个 stat | `TreeWatcher`（FSEvents）只报有变化的文件；没有变化就复用上一轮的结果。拿不准时返回 `.unknown`，退回全量列举，另外每 15 分钟无条件全量一次 |
| 5 | ISO8601 解析每一行都新建两个格式化器 | 改为静态实例；界面上的 `HH:mm` 统一走 `Forecast.clock`（时区自动跟随） |
| 6 | 钩子事件目录每秒轮询一次 | `DirectoryWatch`（kqueue）即时触发；定时器降为 10 秒一次的兜底 |
| 7 | Codex app-server 成功过一次后，只要失败，每轮都会重新拉起进程 | 失败退避 1→2→4…→15 分钟；读输出时只解析新到的行 |
| 8 | 429 且没有 `Retry-After` 时，永远固定等 5 分钟 | 连续被拒按 5/10/20/40 分钟加倍，成功一次后清零；服务器给了 `Retry-After` 就按它的来 |

### C. 小问题

| # | 问题 → 修法 |
|---|---|
| 9 | 倒计时只在快照到达时才动 → `Store.clock` 每分钟发布一次 |
| 10 | 钩子依赖 `/usr/bin/python3`：没装 CLT 时它是个弹框的桩，钩子会静默失效 → 先用 `xcode-select -p` 确认有真 Python，没有就走纯 shell 路径（`PWEBAR_NO_PYTHON=1` 可强制走这条） |
| 11 | Bark 需要 JSON，而我们发的是纯文本 → 地址是 `api.day.app` 或路径为 `/bark…` 时发 JSON |
| 12 | 按天分桶用的是今天的时区偏移 → 改用每个回合当天的偏移；时区标识写进缓存戳 |
| 13 | 子代理的回合会抢占上下文百分比 → 带 `isSidechain` 的回合不再算作「最新回合」 |
| 14 | 周窗口的采样环只覆盖约 50 分钟 → 最小间隔为窗口长度 / 1000，上限 300 个样本（周窗口约覆盖 50 小时） |
| 15 | `history.json` 有两个写者，会互相覆盖 → 写入前读回合并，在最后一次重置处截断 |
| 16 | 「登录时启动」开关只反映意图，不反映实际状态 → 按 `SMAppService.mainApp.status` 回写开关 |

### D. 新增

- **CI**：`.github/workflows/ci.yml`，在 `macos-15` 上依次跑 loccheck（要求 `en.lproj` 无漂移）、钩子脚本与打包副本一致性检查、`swift build`、`swift test`。
- **测试**：`TranscriptTests`、`CodexAppServerTests`、`PushAndBackoffTests`、`WatcherRuntimeTests`，另外在 `HookTests` / `HistoryTests` 里补了用例。
- 改动了三处原有测试，均有理由：
  - `StoreTests`：显式传入 `eventInterval: 1`，因为注入的读取器没有目录可以监听。
  - `HistoryTests`：上限改为引用 `History.cap`。
  - `QuotaTests` / `ForecastFuzzTests`：数组字面量写明 `[TimeInterval?]`，因为 CI 上较旧的 Swift 推断不出类型。

## 证明到了哪一步

| 已证明 | 怎么证明的 |
|---|---|
| macOS 上能编译，212 个测试全过 | CI `macos-15`，提交 `ef64465` 起一直是绿的 |
| FSEvents 和 kqueue 在真内核上会触发，FSEvents 常量不会在运行时崩 | `WatcherRuntimeTests` 在 CI 那台真 Mac 上起了真实的流 |
| 钩子脚本的 Python 路径和纯 shell 路径输出一致 | Linux 上用真实输入对比，加上 `HookTests`（macOS 的 BSD sed 由 CI 跑） |

`WatcherRuntimeTests` 还**抓到过一个真 bug，已修**：FSEvents 报的是 `/private/var/…`，而 `resolvingSymlinksInPath`
会去掉 `/private`，两边对不上，所有事件都被丢掉。现在 `TreeWatcher` 用 `realpath(3)` 把路径翻译回调用方的写法。

**没证明、只有本地 Mac 能答的：**

1. **去重的前提和你的真实日志是否相符。** 先在 `main` 上记下奖杯页（全部范围）的回合数和成本，再切到本分支对比：
   - 应**明显下降**。
   - 带日期的模型 id 应该合并到表里的名字下面，并且有价格。
   - 如果**某天变成 0，或者几乎没变**，说明前提不对。打开一个 `~/.claude/projects/**/*.jsonl`，看 assistant 行有没有
     `message.id` 和 `requestId`，以及同一个 id 是不是真的出现在多行里。
2. **FSEvents 在你真实的 `~/.claude/projects` 上能不能接上**：开着 app 干活，奖杯页和 24 小时图应在 20–40 秒内跟上。
3. **等待提醒**：让 Claude Code 弹出一次权限请求，菜单栏应在约 1 秒内显示（第一次可能要 10 秒，因为事件目录要等第一个事件才会建）。
4. **界面**：
   - 倒计时每分钟会动；
   - 点「移除」后，`~/.claude/settings.json` 里只少了我们那三条，并且生成了 `.pwe-backup-…`；
   - 在系统设置里移除登录项后，app 里的开关会变成关；
   - 跑一遍 `--endurance` 和 `--panel`，用眼睛看一下。

## 不对劲怎么退

各条改动之间没有硬依赖，可以单独撤：

- **监听器**：在 `Transcript.refresh` 里把 `watcher` 设为 `nil`，就退回每轮全量列举；在 `Store` 里不调用 `watchSpool()`，并把 `eventInterval` 的默认值改回 1。
- **去重**：`digest` 的 `counted:` 参数传 `{ _ in false }`，并让 `messageKey` 每行返回不同的值；缓存版本号再加一。
- **按提交 revert**：

## 等你决定的

1. **`Transcript.lastRateLimit()` 和 `ClaudeProvider.init(fallback:)` 仍然没接上**（这是 1.5.0 就存在的死代码）。它读的 `quotaLimits.resetsAt`
   在这一轮没有真实日志可以核对。如果本机日志里真有这个字段，可以把它接成「额度端点读不到时显示的重置时间」。
2. **自建 Bark**：路径不以 `/bark` 开头时，仍按 ntfy 的格式发。要不要在设置里加一个显式的推送类型选项？
3. **合并与发版**：确认上面的真机核对没问题后，合入 `main`，然后跑 `scripts/release.sh 1.6.0`。代码注释里已经按 1.6.0 写了「until 1.6.0」。
4. **CI 的 runner**：`macos-15` 上的 Swift 比本机的 6.4 旧。以后代码用到新语言特性时，应该升级 runner，不要为了迁就 CI 去改代码。
