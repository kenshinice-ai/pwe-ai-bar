# 预报引擎规格（ForecastEngine）2026-09-06

这是 PWE AI Bar 的差异点：别的额度栏都在报「现在用了多少」，只有这里回答「按这个节奏，我到不到得了重置」。
既然是亮点，就不能靠一个拟合出来的数字硬撑。这份规格把预报从「一个点估计 + 视图里散落的 if」重做成
**一个纯函数、一个值类型、一张文案表**。

## 0. 现状与要换掉的东西

`QuotaWindow` 上现在有三个方法：`burn(at:)`、`projectedExhaustion(at:)`、`projectedPercentAtReset(at:)`。
`EnduranceView` 各自调用它们，再用四五段 if/else 拼出标题、大数字、结论句和 OFF 原因。问题有四个：

1. **速率是点估计，却当事实用。** 读数是整数（见 §1 证据），两个相隔十分钟、差 1% 的读数，真实速率可以是 0 也可以是 12%/时。
   现在的代码把它算成 6%/时 并据此画针。
2. **证据强弱只有一个布尔。** `measured` / 开窗平均，二选一。真实世界里还有「刚开始记」「窗口刚滚过」「读数来源换了」「十三小时没读到」。
3. **文案判断在视图里。** 颜色、口径、优先级没有单一出处，新增一个状态要改三处。
4. **不确定性没有出口。** 三个采样点算出的「1 小时 17 分」和三十个采样点算出的长得一模一样。

替换方式：删掉这三个方法，新增 `QuotaWindow.forecast(at:) -> Forecast`。视图只画 `Forecast`，不再自己判断。

## 1. 证据：读数是整数阶梯，不是带噪曲线

本机 `~/Library/Caches/PWE AI Bar/history.json` 的真实记录：

```
claude:five_hour   08:55 20 → 10:00 20 → … → 15:09 20      （六小时纹丝不动）
codex:codex_300    20:53 26 → … → 22:07 26                  （七十四分钟纹丝不动）
claude:seven_day   00:17:47 19 → 00:18:52 20 → 00:21:32 21 → 00:32:47 23
codex:codex_10080  20:53 80 → … → 22:07 80
```

三件事就此定下来：

- **没有一个非整数。** Claude 的 `utilization` 和 Codex 的 `usedPercent` 都是整数。误差不是高斯噪声，是量化。
  所以估计器不该是回归、EWMA 或 Kalman——那些都在平均一个不存在的 ε。
- **平台期是常态。** 大部分时间读数不动。「不动」不是没信息：它是速率的**上界**。
- **同一时刻会被记两次。** `00:18:52` 出现两遍。历史里有重复时间戳，估计器必须先去重，否则除以零。

## 2. 估计器：区间，不是数字

设最近视野内的第一个采样 `(t₁, p₁)`、最后一个 `(tₙ, pₙ)`，`S = tₙ − t₁`（小时），`Δp = pₙ − p₁`。
读数是真实值的取整（无论 round 还是 floor，结论一样），所以真实消耗落在 `(Δp − 1, Δp + 1)`。于是

```
rate.low  = max(0, Δp − 1) / S
rate.high = (Δp + 1) / S
```

两端都是**界**，不是拟合——但要说清楚是**对哪一段的界**：它约束的是 `[t₁, tₙ]` 这段**已经看过**的时间，
对 `[tₙ, 重置]` 不构成任何约束（合上盖子，真实速率就是 0）。§3 的撞线判决因此另有一道门槛，见下。
这一个式子把三种情况统一了：

| 情况 | Δp | 结果 | 含义 |
|---|---|---|---|
| 长时间不动 | 0 | `[0, 1/S]` | 只有上界 → 续航**下界**，可以说「至少还能跑」 |
| 只跨一级 | 1 | `[0, 2/S]` | 下界仍为 0 → 永远不许据此说「会用尽」 |
| 跨多级且时间长 | 6 / 1h | `[5, 7]` | 区间自然收窄 |

**区间宽度就是不确定性的出口**，不需要另设置信度参数。采样少 → 区间宽 → 印不出刻度 → 界面自己降级成「还在采样」。

### 视野（horizon）

沿用现有规则：`horizon = clamp(距重置时间 / 4, 10 分钟, 窗口长度 / 4)`，只取视野内的采样。
这条规则自带一个好性质：一次爆发过去后，`t₁` 停在视野最老一端不动而 `tₙ` 继续前进，`S` 增大、`Δp` 不变，
速率自己衰减。爆发不会永远挂在面板上。

### 回退：开窗平均

视野内不足两个采样、或 `S < 10 分钟` 时，回退到开窗以来的平均：`percent / (observedAt − windowStart)`。
它是**另一个问题的答案**（「这一窗整体多快」而不是「现在多快」），所以它有自己的证据类型，画针时保持空心。
分母用 `observedAt` 而不是 `now`——用时钟做分母会让同一个读数每过一秒就自动变得温和一点。

## 3. 从区间到结论

（`landingHigh` 和判决用同一个锚点。锚在 `observedAt` 而判决锚在 `now`，两者差一个读数年龄，
`.makesIt` 就能印出「到点至少剩 -2%」——判决说撑得到，它自己的落点说超了。同锚之后
`.makesIt ⟺ landingHigh ≤ 100 ⟺ spare ≥ 0` 是恒等式，不需要事后钳位。）

```
remaining      = 100 − percent
enduranceLow   = remaining / rate.high        （最快速率下的保底续航）
enduranceHigh  = rate.low > 0 ? remaining / rate.low : ∞
trip           = resetsAt − now
landingHigh    = percent + rate.high × trip
```

判决**单边**，永远向保守一侧取。下表**就是求值顺序**，从上往下第一条命中的即为结果：

| # | 条件 | verdict | 颜色 |
|---|---|---|---|
| 1 | 读数超过 30 分钟没更新 | `.blind(since:)` | **warm** |
| 2 | 没有重置时间 / 重置已过 | `.noTimeline` | grey（塌缩成一行） |
| 3 | `confirmedExhausted` | `.spent` | hot |
| 4 | 没有百分比 / 读数超过 10 分钟 / 窗口刚开 / 没有窗口长度 | `.sampling` | grey |
| 5 | `enduranceHigh < trip` **且** 证据跨度 ≥ `min(horizon, trip) / 4` | `.fallsShort(gap:)` | hot |
| 6 | `enduranceLow ≥ trip` | `.makesIt(spare: 100 − landingHigh)` | grey |
| 7 | 其余 | `.tooClose` | **warm** |

三处顺序是被对抗审查逼出来的，不是推理出来的：

- **`.blind` 必须排在时间线检查之前。** 十八小时读不到的窗口，它的重置时间多半也已经飘到过去，
  于是先跑的时间线检查会把它吞掉、印出「已过重置时间，等新读数确认」——正好是唯一一块「等」是错误建议的屏幕。
- **触发用「读数多久没更新」而不是 `isStale`。** 不是每个来源都会置这个标志位，而「这条读数是七小时前的」
  本身就是事实，不需要标志位背书。有没有补救措施（「先把连接修好」）另由 `isStale` 决定，只进语音，不进面板。
- **`.fallsShort` 有跨度门槛。** 见 §2：区间是对**看过的那段**的界。十五分钟的证据可以是真读数，
  但它不是对六天以后的预言。看过的时间不足以判断的行程，降级成 `.tooClose`。
  只有撞线这一侧需要这道门槛——另一侧不需要，因为证据薄 → 区间宽 → 快端大 → 本来就够不到 `.makesIt`。

七个判决，对应七种人能分辨、且能采取不同动作的结果：撑得到 / 撑不到 / 说不准 / 等一会 / 去修连接 / 用完了 / 不适用。

**颜色写在模型里，不在视图里。** 之前 `.tooClose` 这类「说不准」用的是默认灰，和「到点还剩 17%」一个样子——
一秒钟扫过去的通道只有「右边有没有红字」，于是「我们不知道」被读成「你没事」。warm 是第三档，必须存在。

## 4. 刻度：向下取整，说「至少」

大数字永远不印区间（`1–2 小时` 不是答案，是把问题退回给用户）。印 `enduranceLow`，并**向下**吸附到一档刻度：

| 量级 | 刻度 |
|---|---|
| < 1 小时 | 5 分 |
| < 6 小时 | 15 分 |
| < 1 天 | 1 小时 |
| ≥ 1 天 | 6 小时 |

向下取整之后它仍然是一个下界，所以文案说「至少能跑」而不是「约」。这一条让「1 小时 17 分」这种
从三个采样点算出来的假精度在结构上印不出来。

**结论句里的时长走同一把尺子。** 缺口也向下吸附。同一个区间的两端用两种精度印出来，
是这份规格自己在破坏自己立的规矩。

另外，视野的下限是「最短可用跨度」的两倍（20 分钟），不是等于它。两者相等时，实测分支在**每个重置前的
最后四十分钟里结构上不可达**——一个正好十分钟宽的采样窗口，里面装得下的跨度必然**小于**十分钟——
于是恰好在问题不再是假设的时候，仪表退回了开窗平均。

## 5. 文案表（规格的一部分，不是视图的自由）

大数字 `= min(endurance, trip)`，左侧小标题**按哪个数赢了**来定，**不按判决**来定。
（判决是 `.makesIt` 时 endurance 必然大于 trip，若按判决取标题，就会在最常见的好消息下把一个
「重置之后才会发生」的时长顶在「到重置」标题下面。）

| verdict | 左标题 | 大数字 | 结论句 | 颜色 |
|---|---|---|---|---|
| `.spent` | 到重置 | trip | 已用尽 | hot |
| `.fallsShort(gap)` | 至少能跑 | enduranceLow | 缺口 2 小时 | hot |
| `.tooClose` | 至少能跑 | enduranceLow | 临界，说不准 | warm |
| `.makesIt(spare)` | 到重置 | trip | 到点至少剩 17% | grey |
| `.sampling` | 到重置 | trip | 还在采样 | grey |
| `.blind(since)` | 到重置 | trip | 7 小时没有新读数 | warm |
| `.noTimeline` | — | — | 这个额度没有重置时间，算不出续航 | grey |

两条硬规则：

- **结论句不许复述大数字。** 大数字说时长，结论句只说大数字说不了的东西（缺口、余量、证据状态）。
- **「没有预报」只有两句话。** 五种「再等等」的原因合并成一句「还在采样」；真正需要动作的
  「很久没读到」独立成句，因为只有它的补救措施不是等待。原因保留为 `thinness` 诊断字段，
  只进 VoiceOver 和自检，不进面板。

## 6. 仪表：区间就是那条带子

区间估计让这张图第一次有了它自己的画法：

- 实心琥珀：`0 → enduranceLow`——**一定跑得到这里**。
- 半透明琥珀：`enduranceLow → min(enduranceHigh, trip)`——**可能跑到这里**。
- 针（三角）落在 `enduranceLow`；实心＝来自采样，空心＝来自开窗平均。
- `enduranceHigh < trip` 时，从 `enduranceHigh` 到闸门画红色尺寸线，那就是**保证存在的缺口**。
- 闸门永远在最右端，横轴永远是 now → reset，不随读数缩放。

`.tooClose` 在图上就是那条半透明带子正好跨过闸门——不需要文字解释。

## 7. 测试

- 区间算术：平台期只给上界；单级跳的下界必须为 0；重复时间戳去重后不得除零。
- 真实回放：`19→20→21→23 / 15 分钟` 的周窗爆发，速率必须落在 `[12, 20]`，且随后续平点自行衰减。
- 判决边界：`enduranceLow == trip` 恰好取 `.makesIt`。
- 刻度：吸附后的值恒 `≤ enduranceLow`。
- 文案：结论句不含大数字的字符串（黄金测试）；七个判决各有唯一颜色档。
- 渲染：11 个敌意状态 × 明暗两套，仍走 `--endurance` 自检。

## 8. 明确不做

- **不做卡尔曼 / 回归 / 指数平滑。** 信号是量化阶梯，不是带噪曲线，那些估计器在处理不存在的噪声。
- **不做多估计器并排显示。** 两个数字摆在 340pt 的面板里，等于把归并工作退回给用户。
- **不做「离线期间平均速率」。** 一句话里给出一个速率再自我否认，读者只会记住那个速率。
  离线只报事实：「7 小时没读到」。
- **不做 11 个状态。** 人能分辨的结果只有 7 个，多出来的状态全部堆在信息量最低的那一格上。

## 9. 对抗审查（2026-09-06 晚）

这份规格写完之后被三个独立的对手 agent 攻击过一轮，各自带一个镜头：**它在哪里声称了它不知道的事**、
**它在这台机器上会不会当场垮掉**、**两秒钟看不看得懂**。前两个跑完，第三个（易读性）撞上会话额度上限没跑。
所以下面这份不是完整的三面审查，缺的那一面按现在的实现自己判的。

跑完的两个一共提出 20 条，其中 7 条判定为致命。落地情况：

| findings | 处理 |
|---|---|
| 区间是对过去那段的界，被当成对未来的界（红色「缺口 5 天以上」出自 15 分钟证据） | **照做**：`.fallsShort` 加跨度门槛，见 §3 第 5 行 |
| `landingHigh` 与判决锚点不同，`spare` 可为负 | **照做**：同锚，见 §3 |
| `.blind` 永远轮不到 / 被时间线检查吞掉 | **照做**：求值顺序前移，见 §3 |
| 回退分支没有定义区间两端 | 实现里本来就是量化区间，非标量 |
| 回退删掉了最小 elapsed 门槛 | 实现里保留了 `elapsed > max(300s, 窗口长度 × 5%)` |
| `.sampling` 没有谓词 | 实现里有五条明确谓词，并记进 `thinness` |
| 实测分支在重置前四十分钟不可达 | **照做**：视野下限抬到 20 分钟，见 §4 |
| 视野随 `now` 每帧重算，读数没变速率却在跳 | **照做**：采样窗口锚在最新一条读数上 |
| 结论句的缺口用原始精度印 | **照做**：同一把刻度尺 |
| 周窗上 §6 的区间带只有约 11pt 宽 | **不改**：七天的横轴上它本来就该窄；那一格的信息由红色尺寸线和结论句承担 |
| `rate.low = 0` 时 `enduranceHigh = ∞`，跨闸门的图形线索不存在 | **不改**：半透明带一路铺到闸门就是「可能刚好够」，渲染出来读得通 |
| `.fallsShort` 的大数字取自 `enduranceLow`、缺口取自 `enduranceHigh`，两者加起来不等于 trip | **不改**：两个数回答两个问题，且都是下界；针与红线画在不同位置，图上分得开 |
